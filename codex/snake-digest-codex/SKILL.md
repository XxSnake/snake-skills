# Snake Digest Codex

把一个复杂主题完成为一份来源可靠、叙事清楚、配图统一、逐页检查过的中文 PDF 小册。

默认读者是聪明但零基础的人。默认语气像一个善于讲故事、尊重事实的朋友。

## 默认交付

在当前工作区创建：

```text
outputs/<slug>/
├─ article.md
├─ sources.md
├─ image_plan.json
├─ images/
│  ├─ img_cover.png
│  ├─ img_01.png
│  └─ ...
├─ <文章标题>.html
└─ <文章标题>.pdf
```

只把最终 PDF 作为主要交付物。保留其余文件用于追溯和后续修改，用户要求时再展示。

## 工作流程

按顺序执行，不要跳过研究、图片检查或 PDF 逐页检查。

### 1. 确认主题

主题足够明确时直接开始。只有以下情况才追问：

- 对象不完整，存在会改变方向的多种理解。
- 用户要求特定受众、篇幅或用途，但关键信息缺失。
- 涉及医疗、法律、投资等高风险内容，需要确认边界。

整本书拆解转用 `book-to-share-pdf`。

### 2. 联网研究

必须搜索当前可靠资料，不能只靠模型记忆。优先级为：

```text
官方或原始文件 > 权威机构 > 主流或专业媒体 > 个人内容
```

在 `sources.md` 中记录每个来源的标题、链接、发布日期、所支持的事实和可信度。重要事实使用一个可靠原始来源，或两个相互独立的可靠来源支持。无法确认时使用保守表述，不要补写细节。

### 3. 选择叙事骨架

选择一个主骨架，必要时少量混用：

- 时间线：起源、发展、转折、现状与后果。
- 概念递进：日常类比、正式概念、机制、案例与意义。
- 多角度扫描：角色或区域、彼此关系、关键变量与后续观察。
- 问题链：现象、连续追问、根因与推演。

### 4. 写文章

先写 `article.md`，再规划图片。遵守这些要求：

- 开篇 3 至 5 句话用真实场景、反差、数据或问题抓住读者。
- 专业术语第一次出现时，先用白话解释，再给正式名称。
- 优先使用奶茶店、租房、网购、排队等日常类比。
- 章节标题像朋友聊天，不使用“第一章：概述”等论文式标题。
- 准确性优先于故事性，不确定信息明确标注。
- 避免“首先、其次、综上所述、赋能、抓手”等模板化表达。
- 不把命令、图片计划、长代码或 JSON 放进正文。
- 末尾保留“资料来源与延伸阅读”。

可视化组件的写法和版面约束见 `references/pdf_design_guide.md`。只在它们能帮助理解时使用，避免连续堆叠色块。

### 5. 规划图片

读取 `references/image_prompt_guide.md`，并按 `templates/image_plan_template.json` 建立 `image_plan.json`。

默认生成 1 张竖版封面图和 2 至 4 张横版正文图。只有内容确实复杂时才增加到 5 至 6 张正文图，不为凑数量生成装饰图。

图片优先承担以下作用：

- 把抽象机制变成日常场景。
- 还原关键历史场景。
- 用具象隐喻解释关系或因果。
- 营造与主题一致的封面氛围。

不要让生成图片承担精确数据、流程文字或标签；这些内容使用正文和轻量 HTML 组件表达。

### 6. 使用 ChatGPT 内置图像模型

配图必须调用 ChatGPT 内置图像模型：先遵循 `imagegen` 技能，再使用内置 `image_gen` 工具逐张生成。最终只接受 PNG、JPG、JPEG 或 WebP 位图。每个不同画面单独调用一次，生成后立即检查主题、构图、色调、文字残留和人物风险。

内置工具通常先把图片保存在 `$CODEX_HOME/generated_images/`。选定结果后，将它复制或移动到当前项目的 `outputs/<slug>/images/`，并改成 `image_plan.json` 约定的稳定文件名。不要让项目引用的最终图片只留在 Codex 默认目录。

不得生成或使用 SVG，也不得用 Mermaid、HTML/CSS、程序绘图、截图、二维码或占位图冒充插画。不要把 SVG 转成位图来规避这条要求。不得静默切换到其他模型或需要 API 密钥的路线。如果 ChatGPT 内置图像模型不可用，说明原因并停在 PDF 合成前；只有用户明确同意时，才按 `imagegen` 技能提供的备用路线继续。

`validate_digest.py` 只能检查文件、尺寸、重复项和计划一致性，不能证明图片的生成来源。图片来源必须由实际执行过程保证，不要把“检查通过”表述成来源证明。

### 7. 检查文章与图片

运行：

```bash
python scripts/validate_digest.py outputs/<slug>/article.md outputs/<slug>/image_plan.json outputs/<slug>/images --strict
```

严格模式必须拦截：缺图、重复图片、封面方向错误、正文图方向错误、计划与正文不一致、过小图片、正文 SVG 或 Mermaid、缺少 `sources.md`。

### 8. 生成 PDF

使用自动渲染引擎。Windows 会优先使用已安装的 Edge 或 Chrome；其他环境会选择可用浏览器或 WeasyPrint。不要通过可见的浏览器“打印”界面手动另存。

```bash
python scripts/merge_images.py \
  outputs/<slug>/article.md \
  outputs/<slug>/images \
  outputs/<slug>/final.pdf \
  --title "标题" \
  --subtitle "一口气搞懂这个主题" \
  --author "@潇潇蛇" \
  --qr-image references/wechat_qr.jpg \
  --cover-image outputs/<slug>/images/img_cover.png \
  --strict \
  --engine auto
```

脚本把 `final.pdf` 自动改成文章标题，并同步生成同名 HTML。

### 9. 验证并逐页查看

运行：

```bash
python scripts/verify_digest_pdf.py outputs/<slug>/<文章标题>.pdf --render --out-dir outputs/<slug>/_pdf_renders
```

必须查看全部页面图片，确认：

- 没有乱码、截断、重叠、空白异常或本地文件地址。
- 封面标题清楚，图片没有被错误裁掉。
- 页眉、页脚、页码、来源页和章节转场正常。
- 色块克制，插图清晰且服务于理解。

发现问题后修正并重新生成、重新查看。没有完成逐页查看，不得交付。

## 视觉方向

默认使用“泛黄纸张上的轻杂志小册子”：暖黄、米白、棕褐、低饱和、细边框和充足留白。正文图片默认 `normal`，正文 `hero` 最多一张。完整规则见 `references/pdf_design_guide.md`。

## 失败处理

- 资料不足：继续搜索；仍不足时缩小结论并明确限制。
- 图片生成失败：不要用假图补位；保留文章和图片计划，说明阻碍。
- PDF 引擎失败：先让自动模式尝试另一种可用引擎；仍失败时保留 HTML 和文章，明确说明没有生成最终 PDF。
- 逐页检查发现问题：修复后重新生成，不交付半成品。

## 交付回复

用简短中文给出最终 PDF 链接，说明资料和图片是否完整，以及任何仍会影响理解的限制。不要把整篇文章复制到聊天中。
