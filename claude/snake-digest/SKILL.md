# Snake Digest —— 一口气搞懂一件事

> **方法论来源**
> 灵感来源于B站/抖音财经科普博主"小Lin说"（Lindsay）的叙事方法论。小Lin的核心能力是把复杂的财经、商业、技术概念讲到零基础的人能听懂，同时不失专业深度。Snake Digest将这套方法论从视频形式适配为文字长文，服务于一个核心目标：**让门外汉读完后真正搞懂一件事**。

你正在执行一次Snake Digest科普长文写作。最终产出一份**排版精美的PDF长文**。

---

## 前置准备

### 环境准备

1. **确认PDF转换脚本可用**：本Skill自带 `scripts/md_to_pdf.py`（基于WeasyPrint），用于将最终Markdown转为PDF。确保依赖已安装：`pip install weasyprint markdown --break-system-packages`。

### 明确主题

拿到用户输入后，确认以下信息。如果用户已经给得足够明确（比如"帮我一口气搞懂期货"），不需要追问，直接开始：

1. **主题**：用户想搞懂什么？
2. **类型判断**（你自己判断，不用问用户）：这个主题适合哪种叙事模型？（见下文）
3. **用户的起点**：默认假设为零基础。如果用户明确说了自己的背景（比如"我知道股票但不懂期货"），以此为基准调整起点。

## 第一步：信息收集

**必须联网搜索**，不能仅靠已有知识。科普长文的可信度取决于信息的准确性和丰富度。

### 搜索目标

围绕以下维度搜集素材（不是每个维度都适用，按主题灵活取舍）：

- **基本定义和核心机制**：这个东西到底是什么？它的底层运作逻辑是什么？
- **起源故事**：它是怎么来的？谁发明/发起的？为什么会出现？
- **发展脉络**：从诞生到现在经历了什么？有没有标志性的转折点？
- **关键数据**：支撑理解的核心数字（规模、增速、占比等）
- **经典案例/故事**：有没有戏剧性的真实事件可以用来说明问题？
- **争议和批评**：有没有反对声音？常见的误解是什么？
- **跟普通人的关系**：这件事跟日常生活有什么关联？

### 搜索策略

- 多次搜索、多关键词组合，不要只搜一次
- 一手来源优于二手来源（官方文件 > 权威媒体 > 转载/聚合）
- 搜集具体的数字、时间、人名、事件——这些是故事的骨架
- 特别注意搜集**好故事**：真实事件中有戏剧冲突的案例，这是让读者记住的关键

### 信息充分性自检

搜索完成后检查：
- 我能不能用一句大白话告诉别人"这个东西是什么"？
- 我有没有足够的故事和案例来把道理讲活？
- 核心数据够不够支撑关键论点？
- 有没有类比素材可以拉近读者距离？

信息不够就再补搜。不要凑合。

## 第二步：选择叙事模型

根据主题类型，从以下四种模型中选择最合适的一种。模型决定了文章的**骨架**，具体章节内容是灵活的。

### 模型A：时间线叙事

**适用场景**：讲一个国家/公司/行业/事件的来龙去脉——主题有一个明确的"故事"可以从头讲到尾。

**结构逻辑**：起源 → 发展 → 高潮/转折 → 现状 → 未来展望

**结构范例**（以"委内瑞拉经济崩溃"为参考）：
```
钩子：一个震撼性的现实场景或数据
一切的开始：背景和起源
黄金年代：鼎盛时期（如果有的话）
转折来了：危机的种子
事情开始失控：恶化过程
到底烂到什么程度？：现状全景
所以问题出在哪？：归因分析
还有救吗？：未来推演
```

**关键要求**：章节之间要有因果连接，每一节的结尾自然引出下一节的开头。读者要感受到"一步步走到这里"的逻辑链条，而不是跳跃式的信息罗列。

### 模型B：概念递进

**适用场景**：讲清楚一个概念、机制或技术——主题本身是一个"东西"而不是一个"故事"。

**结构逻辑**：是什么（类比入门）→ 怎么运作 → 进阶理解 → 真实案例验证 → 本质提炼

**结构范例**（以"期货"为参考）：
```
钩子：一个让人意外的事实或问题
先打个比方：用日常场景解释核心概念
那它具体是怎么玩的？：运作机制
等等，还有更刺激的：进阶概念（做空、杠杆等）
来看个真实案例：经典故事（如英镑崩盘）
所以期货的本质是什么？：框架提炼
跟我有什么关系？：生活连接
```

**关键要求**：第一个类比是整篇文章的锚点，后面的概念都要能连回这个类比。比如用"奶茶店"解释了供需，后面讲期货、对冲、做空时都继续用奶茶店这个场景延伸，读者不用每次重新理解一个新的世界。

### 模型C：多角度扫描

**适用场景**：讲一个宏观全景——主题涉及多个并行的维度/区域/领域，需要逐一扫过。

**结构逻辑**：全景概述 → 分区块逐一深入 → 区块之间的关联 → 全景总结

**结构范例**（以"全球经济2025"为参考）：
```
钩子：一个统领全局的观察
先看大盘：全景概述和关键趋势
美国这边怎么样？
中国这边呢？
日本有点意思：
欧洲的情况：
最值得关注的几个信号：跨区块的关联
接下来会怎样？：趋势判断
```

**关键要求**：每个区块不是孤立的小作文，而是要跟全景论点呼应。每讲完一个区块，用一两句话把它连回到整体图景中。

### 模型D：问题链

**适用场景**：讲清楚一个现象背后的原因——主题的核心是"为什么"。

**结构逻辑**：现象 → 第一层追问 → 第二层追问 → 第三层追问 → 根因 → 推演

**结构范例**（以"黄金为什么涨"为参考）：
```
钩子：现象呈现（黄金突破历史新高）
为什么涨？：表面原因
背后的三股力量：更深的驱动因素
等一下，白银为什么涨得更猛？：对照追问
那为什么后来又跌了？：反向追问
所以到底什么决定了金价？：框架提炼
```

**关键要求**：每一层追问都要比前一层深一层，不能在同一层面反复打转。读者要感受到"越挖越深"的探索感。

## 第三步：写作

### 零知识假设——这是最核心的原则

**默认读者对这个领域的知识为零。** 这不是说读者笨，而是说读者聪明但从未接触过这个领域。

具体执行规则：

**1. 每个专业术语第一次出现时，必须先"翻译"再使用**

不要写：
> 期货的本质是标准化的远期合约，交易双方约定在未来特定日期以特定价格买卖特定资产。

要写：
> 想象你开了一家奶茶店，珍珠是你的核心原料。你担心下个月珍珠涨价，于是跟供应商提前约定：不管到时候市场价多少，我都按今天这个价买。供应商呢，他担心珍珠跌价，所以也乐意锁定一个价格。这个"提前约好价格、到时候必须执行"的约定，就是期货的雏形。金融市场把这个过程标准化、搬到交易所里，就成了我们说的期货合约。

**2. 类比必须来自日常生活**

好的类比素材：奶茶店、点外卖、租房、打游戏、网购、排队、赌博、打麻将、存钱罐、菜市场。
坏的类比素材：其他同样需要背景知识的专业领域。

**3. 先类比，后术语，再回扣**

固定节奏：
1. 用日常场景讲明白道理（读者：哦我懂了）
2. 引入正式术语（读者：原来这个叫XX啊）
3. 用术语回到真实世界验证（读者：这个术语我记住了，因为我知道它在真实世界里长什么样）

### 叙事驱动——讲故事，不是做PPT

**1. 钩子开头（全文最重要的100字）**

开篇必须在3-5句话内抓住读者。三种有效的钩子模式：

- **震撼数据型**："2023年，全球有超过400万人因为一种叫做'稳定币'的东西损失了全部积蓄。但讽刺的是，'稳定'正是它名字里最大的谎言。"
- **荒谬反差型**："世界上最大的石油储量在委内瑞拉。但委内瑞拉人买一卷卫生纸，需要排队两个小时。"
- **直接提问型**："你有没有想过，为什么黄金这么贵？它不能吃、不能住、不能用来发电，凭什么一小块就值几万块？"

**不要** 用的开头："今天我们来聊聊XX"、"XX是一个重要的概念"、"在当今社会"。

**2. 章节标题要像跟朋友聊天时说的话**

好的章节标题：
- "所以钱到底去哪了？"
- "转折来了"
- "等等，还有更离谱的"
- "那代价是什么？"
- "说了这么多，跟我有什么关系？"

不好的章节标题：
- "第一章：概述"
- "3.2 影响因素分析"
- "小结"

**3. 故事嵌数据，不是数据配文字**

数据不要堆在一起。每个关键数据应该嵌入一个叙事场景中：

不要写：
> 委内瑞拉2018年通胀率达到1,698,488%，GDP连续五年负增长，石油产量从2015年的260万桶/天下降到2020年的40万桶/天。

要写：
> 到了2018年，事情已经疯到什么地步呢？一杯咖啡的价格，早上和下午可以差一倍。官方数字是通胀率1,698,488%——对，你没看错，将近170万percent。你上个月发的工资，这个月就只能买半瓶矿泉水了。与此同时，明明坐拥全世界最大的石油储量，他们的日产量却从260万桶暴跌到40万桶。石油是他们唯一的经济支柱，支柱塌了，整栋楼也就完了。

**4. 节奏感——长短句交替，段落有呼吸**

不要每段都一样长。偶尔用一句话自成一段来制造重点：

> ……所有人都觉得这套模式可以永远运转下去。
>
> 直到油价跌了。

**5. 段落之间要有"桥"**

每一节的结尾，自然过渡到下一节。不要硬切，要让读者感受到"接着往下看"的引力：

> 所以到这里，我们搞清楚了期货是什么。但你可能会问：既然是提前约好价格，那万一到时候市价比约定价低很多怎么办？卖方不就亏了吗？
>
> 这就引出了期货里最刺激的部分——做空。

### 归因总结——带走一个框架

**最后一节不是"总结全文"，而是"提炼框架"。**

目标：读者合上文章后，脑子里留下一个可以复用的认知模型。

好的结尾：
> 所以你看，金价的涨跌归根到底就是三股力量的拔河：避险需求把它往上拉，利率把它往下拽，而央行购金量决定了绳子中间的锚点在哪里。任何时候看到黄金大涨大跌，你只要问三个问题：世界是不是变得更不确定了？美联储是在加息还是降息？各国央行是在买黄金还是在卖？搞清楚这三个问题，你就能看懂八成的金价波动。

不好的结尾：
> 综上所述，黄金价格受到多种因素的综合影响，包括地缘政治、货币政策和市场供需等。

## 写作风格

### 要做到的

- **聊天感**：像一个懂行的朋友在跟你解释，不是教授在讲课
- **具体**：每个论点都有具体的数字、时间、人名、事件支撑
- **诚实**：搜不到的信息标注「该信息暂缺」，拿不准的判断标注「这一点我不完全确定」
- **有判断**：该给观点的地方给观点，但标注"我的理解是"或"从目前信息来看"
- **有节奏**：长短句交替，段落长短交替，紧张和舒缓交替

### 绝对禁区

- **AI套话**："首先...其次...最后"、"综上所述"、"值得注意的是"、"不难发现"、"众所周知"
- **空洞形容**："赋能"、"抓手"、"打造闭环"、"具有重要意义"
- **教科书开头**："在当今XX快速发展的时代"、"随着XX的不断进步"
- **高频踩雷词**："说白了"、"意味着什么？"、"本质上"、"换句话说"、"不可否认"
- **虚假类比**：不要为了类比而类比，如果没有找到真正贴切的日常场景，宁可直接用白话解释
- **编造信息**：绝不编造数据、事件或案例

## 可视化组件——让概念"看得见"

纯文字再好也有极限。好的科普长文应该像杂志一样，在关键位置用视觉元素帮助读者理解。PDF脚本已经内置了一套可视化组件的CSS样式，你只需要在Markdown中插入对应的HTML代码块即可。

### 使用原则

1. **每隔2-3个章节至少插入一个可视化元素**，不要让读者连续阅读大段纯文字
2. **可视化是为理解服务的，不是装饰**——每个图表/卡片都要传达一个具体的信息点
3. **选择最合适的组件类型**——不要什么都用表格，也不要什么都用流程图

### 组件速查表

#### 1. 划重点框 `key-point`
**用途**：一句话总结核心概念，让读者一眼抓住重点。适合在一段解释之后"画龙点睛"。

```html
<div class="key-point">
  <span class="label">划重点</span>
  <span class="content">期货的本质就是一份"关于未来价格的约定"——今天定价格，未来交货。</span>
</div>
```

#### 2. 大数字 `big-number`
**用途**：突出展示一个震撼性的关键数字。适合开篇的钩子或论证中的关键数据。

```html
<div class="big-number">
  <span class="number">1,698,488<span class="unit">%</span></span>
  <span class="desc">2018年委内瑞拉通胀率</span>
</div>
```

#### 3. 数字卡片行 `number-row`
**用途**：并排展示2-4个关键数字做对比。适合快速呈现一组关联指标。

```html
<div class="number-row">
  <div class="number-card">
    <span class="val">260万</span>
    <span class="lbl">2015年日产量（桶）</span>
  </div>
  <div class="number-card">
    <span class="val">40万</span>
    <span class="lbl">2020年日产量（桶）</span>
  </div>
  <div class="number-card">
    <span class="val">-85%</span>
    <span class="lbl">降幅</span>
  </div>
</div>
```

#### 4. 类比框 `analogy-box`
**用途**：左边是日常场景，右边是对应的专业概念。这是snake-digest的灵魂组件——用最直观的方式让读者建立映射关系。

```html
<div class="analogy-box">
  <div class="daily">
    <span class="side-label">生活中的场景</span>
    <span class="side-content">你跟房东签了一年租约，不管周边房租怎么涨，你都按约定价住着。</span>
  </div>
  <div class="arrow">→</div>
  <div class="pro">
    <span class="side-label">对应的金融概念</span>
    <span class="side-content">这就是<strong>远期合约</strong>——双方约定在未来某个时间点，按今天商定的价格执行交易。</span>
  </div>
</div>
```

#### 5. 对比卡片 `vs-box`
**用途**：A vs B两个概念的对比。适合厘清容易混淆的概念。

```html
<div class="vs-box">
  <div class="vs-card">
    <span class="vs-title">套期保值者</span>
    <span class="vs-content">真正需要买/卖货的人。奶茶店锁定珍珠价格、航空公司锁定油价。目的是<strong>规避风险</strong>。</span>
  </div>
  <div class="vs-card">
    <span class="vs-title">投机者</span>
    <span class="vs-content">不需要货，纯粹判断价格涨跌来赚钱。目的是<strong>承担风险、赚取差价</strong>。</span>
  </div>
</div>
```

#### 6. 时间线 `timeline`
**用途**：标记关键时间节点。适合回顾发展历程或事件经过。

```html
<div class="timeline">
  <div class="event">
    <span class="year">1848</span>
    <span class="what">芝加哥期货交易所（CBOT）成立，现代期货市场诞生</span>
  </div>
  <div class="event">
    <span class="year">1972</span>
    <span class="what">芝加哥商业交易所推出外汇期货，金融期货时代开启</span>
  </div>
  <div class="event">
    <span class="year">1992</span>
    <span class="what">索罗斯做空英镑，一天赚10亿美元，"黑色星期三"</span>
  </div>
</div>
```

#### 7. 流程步骤条 `flow-steps`
**用途**：展示一个过程的几个关键步骤。适合解释"某件事是怎么运作的"。

```html
<div class="flow-steps">
  <div class="step"><span class="step-num">①</span>买方和卖方<br>各自下单</div>
  <span class="flow-arrow">→</span>
  <div class="step"><span class="step-num">②</span>交易所撮合<br>生成合约</div>
  <span class="flow-arrow">→</span>
  <div class="step"><span class="step-num">③</span>双方缴纳<br>保证金</div>
  <span class="flow-arrow">→</span>
  <div class="step"><span class="step-num">④</span>到期日<br>交割或平仓</div>
</div>
```

#### 8. 知识卡片 `info-card`
**用途**：补充一个背景知识或小贴士。适合插入"顺便说一下"的辅助信息，不打断主线叙事。

```html
<div class="info-card">
  <span class="info-label">小知识</span>
  为什么期货交易所最早出现在芝加哥？因为芝加哥是当时美国中西部的粮食集散地，农民需要在收获前锁定粮价，商人需要在买入前锁定成本——两边的需求天然匹配。
</div>
```

#### 9. 自定义SVG图表 `diagram`
**用途**：需要完全自定义的示意图、关系图、简易图表时使用。直接在Markdown中写inline SVG。

```html
<div class="diagram">
  <svg width="400" height="120" viewBox="0 0 400 120" xmlns="http://www.w3.org/2000/svg">
    <!-- 在这里画你的图 -->
  </svg>
  <span class="caption">图：期货市场的风险转移机制</span>
</div>
```

### 组件使用决策

| 你想传达的信息 | 推荐组件 |
|---|---|
| 一句话总结刚讲的核心概念 | `key-point` |
| 一个震撼的数字 | `big-number` |
| 一组对比数字 | `number-row` |
| "日常生活中的XX其实就是专业领域的YY" | `analogy-box` |
| A和B有什么区别？ | `vs-box` |
| 事情是按什么顺序发生的？ | `timeline` |
| 某个机制是怎么运作的？ | `flow-steps` |
| 顺便补充一个背景知识 | `info-card` |
| 以上都不合适，需要自定义图形 | `diagram` + SVG |

### Markdown写作规范

## 第五步（按需）：配图

**触发条件**：用户看完PDF后说"配图"、"给我配图"、"加图片"等。如果用户没提，不要主动进入这一步。

### 配图流程

当用户触发配图后，执行以下操作：

**1. 分析文章，确定插图位置**

回顾已完成的文章，选择3-6个最适合插图的位置。优先选择：
- 类比场景（刚用日常场景解释了一个概念的位置）
- 历史故事/案例（有画面感的叙事段落）
- 核心机制（需要视觉化帮助理解的复杂关系）
- 对比概念（两个概念需要区分的位置）

避免在已有可视化组件（key-point、vs-box等）的位置重复插图。

**同时构思一张封面图**——这张图不插入文章正文，而是用作PDF封面的满铺背景。封面图的要求：
- 构图大气、视觉冲击力强，适合铺满整个A4页面
- 能一眼传达文章的主题或核心意象
- 不要有具体的场景细节（那是正文插图的事），更偏氛围和概念感

**2. 在文章MD中插入占位符**

在选定位置插入占位符，格式：
```
<!--IMG:img_01:图片说明文字-->
```

更新文章MD文件（覆盖原文件）。

**3. 输出图片任务文件**

生成 `[主题名]_图片任务.md`，用户直接复制粘贴给ChatGPT。格式参考 `references/gpt_image_prompt.md`，结构如下：

```markdown
# 图片生成任务：[文章标题]

请按以下清单逐张生成图片。每张生成后我会下载保存。

## 统一风格要求

- 风格：暖色调水彩/淡彩插画（warm-toned watercolor editorial illustration）
- 色调：偏暖黄、米白、棕褐，与泛黄纸张背景协调
- 构图：简洁清晰，主体突出
- 比例：正文插图用横版 16:9，封面图用竖版 9:16
- 硬性规则：画面中不要出现任何文字、字母、数字、标签

## 图片清单

### 封面图（保存为 img_cover.png）

**用途**：PDF封面满铺背景图，需要大气、有视觉冲击力
**比例**：竖版 9:16（注意：封面图是竖版，跟正文插图的横版16:9不同）

**Prompt**：
warm-toned watercolor editorial illustration, [宏观概念性描述], grand cinematic composition, atmospheric, vertical 9:16 portrait format, soft golden lighting, no text no labels no letters no numbers in the image

---

### 第1张（保存为 img_01.png）

**要画什么**：[中文描述]

**Prompt**：
warm-toned watercolor editorial illustration, [英文描述], soft golden lighting, clean composition, no text no labels no letters no numbers in the image

---

（以此类推）
```

**Prompt写作规则**：
- 每张开头锚定 `warm-toned watercolor editorial illustration`
- 每张末尾加 `no text no labels no letters no numbers in the image`
- 中文描述让用户看懂画的是什么，英文Prompt给模型用，两个都写
- 场景要具体——有人物、有环境、有动作、有光线
- 文件名 `img_01.png` 递增，与占位符ID一一对应

**4. 交付两个文件，等待用户生图**

告诉用户：
- 把图片任务文件的内容粘贴给ChatGPT
- 下载生成的图片（按文件名保存）
- 上传回来

**5. 用户上传图片后，合成最终PDF**

用户上传图片后，运行合成脚本。注意 `img_cover.png` 用作封面背景，不走占位符合成：

```bash
# 收集图片到一个目录
mkdir -p /home/claude/digest_images
cp /mnt/user-data/uploads/img_*.png /home/claude/digest_images/

# 合成（img_cover.png 通过 --cover-image 传入，微信二维码已存在skill目录下）
python [skill目录]/scripts/merge_images.py 文章.md /home/claude/digest_images/ output.pdf \
  --title "标题" --subtitle "一口气搞懂XXX" \
  --cover-image /home/claude/digest_images/img_cover.png \
  --qr-image [skill目录]/references/wechat_qr.jpg
```

## 篇幅指南

| 主题复杂度 | 字数范围 | 典型场景 |
|-----------|---------|---------|
| 单一概念 | 3,000 - 6,000字 | 期货、稳定币、做空、量化宽松 |
| 行业/现象 | 6,000 - 12,000字 | 新能源汽车行业、IP经济、外卖商战 |
| 国家/宏观 | 10,000 - 18,000字 | 委内瑞拉经济、全球经济年度回顾 |

核心原则：**以讲清楚为标准，不以字数为目标。** 能3000字讲透的不要注水到6000字，需要15000字才能讲透的不要硬压到8000字。

## 质检清单

交付前自检：

- [ ] 读完后，一个零基础的人能不能跟朋友复述这件事的核心逻辑？
- [ ] 每个专业术语第一次出现时都有类比或白话翻译？
- [ ] 开头的钩子够不够抓人？读者有没有理由继续往下看？
- [ ] 章节标题是口语化的问题/短句，不是学术编号？
- [ ] 有没有真实的故事/案例让概念落地？
- [ ] 关键数据嵌入了叙事场景中，而不是干巴巴地列出来？
- [ ] 段落之间有自然过渡，读起来有"停不下来"的感觉？
- [ ] 每隔2-3个章节至少有一个可视化组件（表格/卡片/图表）？
- [ ] 最后一节提炼了一个读者可以带走的认知框架？
- [ ] 没有触犯绝对禁区里的任何一条？
- [ ] 搜不到的信息诚实标注了，没有编造？
- [ ] PDF排版美观、可读性好？
